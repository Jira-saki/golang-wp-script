# 🐉 golang-wp-script

![Go Version](https://img.shields.io/badge/Go-1.21+-00ADD8?logo=go&logoColor=white)
![Build](https://img.shields.io/badge/build-passing-brightgreen)
![License](https://img.shields.io/badge/license-MIT-blue)
![Platform](https://img.shields.io/badge/platform-Linux%20amd64-lightgrey)

A high-performance, lightweight DevSecOps toolkit written in Go — built for automating security audits, monitoring uptimes, and hunting malware across multi-tenant WordPress shared hosting environments (e.g., Xserver).

Instead of relying on resource-heavy plugins, this repo compiles into standalone native binaries (~2.5MB–3.3MB) that run fast with a minimal footprint.

---

## 📋 Prerequisites

Before building or deploying, make sure you have the following:

| Requirement | Version | Notes |
|---|---|---|
| [Go](https://go.dev/dl/) | 1.21+ | Required for local cross-compilation |
| SSH access | — | Required to deploy binaries to the hosting server |
| Linux target server | amd64 | Shared hosting (e.g., Xserver) |
| `scp` or `rsync` | — | For transferring compiled binaries |

> **No Go runtime is needed on the target server.** Binaries are fully self-contained.

## 🎯 Component Breakdown

| Binary | Size | Purpose | Core Technology |
|---|---|---|---|

| `cli-template` | ~2.5 MB | Boilerplate scaffold for rapidly building new automation utilities | Standard Go I/O flags |

## 🛠️ Build & Deploy

All tools are cross-compiled locally and deployed as self-contained binaries — no Go runtime required on the server.

```bash
# Compile for Linux amd64
GOOS=linux GOARCH=amd64 go build -o bin/xserver-walker ./cmd/walker
GOOS=linux GOARCH=amd64 go build -o bin/prober ./cmd/prober
GOOS=linux GOARCH=amd64 go build -o bin/cli-template ./cmd/cli-template

# Deploy to your hosting server
scp bin/xserver-walker bin/prober xserver:~/
```

## 💻 Operational Workflows

### 1. Malware Hunting (`xserver-walker`)

Navigate into the target tenant domain directory and run the scanner:

```bash
cd /home/user/target-domain.com
../xserver-walker
```

> **Smart Noise Filtering:** Automatically skips benign 0-byte `index.php` routing stubs and internal config arrays generated by trusted platforms like All In One Security (`firewall-rules/settings.php`).

---

### 2. Bulk Scan Macro (`scanwp`)

Add this function to `~/.bashrc` to scan all tenant domains in a single command:

```bash
scanwp() {
  echo "🚀 [DevSecOps] Starting Global WordPress Security Scan..."
  echo "========================================"
  cd ~ || return
  for dir in */ ; do
    if [ -d "${dir}public_html" ]; then
      echo "🏢 [SCANNING] Domain: ${dir%/}"
      cd "$dir" && ../xserver-walker && cd ..
      echo "========================================"
    fi
  done
}
```

Run `scanwp` from any shell session to sequentially audit all tenant spaces.

## 🧪 Testing & Verification

To verify that the scanner's logic accurately flags suspicious files while successfully suppressing noise (False Positives), you can execute the following verification steps in a safe test directory:

### 1. Simulate a False Positive (Should be Ignored)

Create a standard 0-byte `index.php` stub inside a writeable assets directory (commonly used by plugins to prevent directory listings). The scanner's suppression engine should catch this and skip alerting:

```bash
# Create a test directory structure
mkdir -p public_html/wp-content/uploads/backup/2026
touch public_html/wp-content/uploads/backup/2026/index.php

# Execute scan
../xserver-walker
# ✅ Output: Completed cleanly with no alerts.
```

## 🚨 Incident Response Case Study

This toolkit was battle-tested during a live production remediation. While integrating the `scanwp` macro, the scanner detected a stealthy, persistent Base64 payload injected directly into `~/.bashrc`.

The attacker used:
- A fake comment header (`# DO NOT REMOVE THIS LINE. SEED PRNG. #defunct-kernel`) to disguise the payload
- A spoofed process name (`exec -a '[card0-crtc8]'`) to blend into system process lists

This repository provided the detection baseline needed to fully neutralize, trace, and eradicate the malware lifecycle.
